`data-section.md` (original research/concept notes). If those three disagree, this file is the

## 2. What's built — Phase 1: Blue Economy Observatory

Homepage teaser (`#insights` on `index.html`) + full page (`insights.html`): headline stat tiles
and two hand-drawn `<canvas>` charts (top short-sea shipping nations; short-sea vs. other freight
split), sourced from Eurostat's open dissemination API (no key required).

- **`js/observatory.js`** — three-layer resilience: live Eurostat fetch → committed snapshot
  (`assets/data/observatory.json`) → hardcoded fallback constants. Skips draw-in animation under
  `prefers-reduced-motion`/`body.lite`.
- **`assets/data/observatory.json`** — committed snapshot, regenerated by
  **`scripts/fetch-eurostat.sh`**.
- Datasets: `mar_go_qm` (quarterly goods, IN+OUT summed) and `mar_sg_am_cw` (short-sea shipping by
  country).

## 3. What's built — Phase 2: Fleet Watch world map

One canvas map, Bering Strait to the Drake Passage: real (simplified) world coastline, 15
chokepoint markers (tiered major/secondary), 5 major trade-route lines, and live AIS ship blips —
plus a "vessels tracked now" counter, a live "busiest chokepoint" readout, and a lat/lon HUD on
hover.

- **`js/fleetwatch.js`** — polls `assets/data/fleet-live.json` every ~9s; loads
  `assets/data/chokepoints.json` and `assets/data/routes.json` once; draws everything on
  `<canvas>`. The static layer (graticule/coastline/routes/chokepoint rings — now just the DOM
  dots, see §4) is cached to an offscreen canvas and blitted every frame; only ship dots redraw
  per-frame, so the much larger 50m coastline (§4) doesn't jank the animation.
- **`assets/data/chokepoints.json`** — 15 real, sourced chokepoints: Gibraltar, Dover, Danish
  Straits, Bosphorus, Suez, Bab-el-Mandeb (original six) + Hormuz, Malacca, Panama Canal, Cape of
  Good Hope, Tsushima, Taiwan Strait, Bering Strait, Torres Strait, Drake Passage. Each has
  `tier: "major"|"secondary"`, a `bbox` (also used by the relay — see §7), a real current-events
  summary, and a source link.
- **`assets/data/routes.json`** — 5 major global trade routes (Asia–Europe, Transpacific,
  Transatlantic, Middle East–Asia energy, Asia–Panama–US East Coast), each with waypoints, a real
  sourced summary, and a source link.
- **`assets/data/coastline.json`** — see §4 for the current (50m) version.
- **`scripts/fleet-relay/`** — the live-data engine, running on the VPS as a systemd service:
  - `relay.py` — one persistent WebSocket connection to aisstream.io, subscribed to one small
    bounding box per chokepoint (derived automatically from `chokepoints.json` at startup — adding
    a chokepoint widens live coverage with no code change). Writes `assets/data/fleet-live.json`
    atomically every 5s.
  - `requirements.txt` — just `websockets`.
  - `fleet-relay.service` — the systemd unit (installed at `/etc/systemd/system/` on the VPS).
- `assets/data/fleet-live.json` is generated on the VPS, gitignored, never committed.

## 4. What's built — today's map bug fixes

Three bugs Federico reported against the live map, all root-caused and fixed:

1. **Routes crossing the Pacific incorrectly** — 2 of 5 routes (Transpacific,
   Asia–Panama–US East Coast) cross the antimeridian (±180° longitude); a plain `lineTo` between
   raw lon/lat drew a straight line the "wrong way round" through Asia/Europe instead of wrapping
   across the Pacific. Fixed with a `strokeGeoPolyline()` helper in `js/fleetwatch.js` that splits
   any line at a >180° longitude jump and resumes it on the opposite map edge — used for both
   routes and coastline.
2. **Two markers per chokepoint** — `renderStatic()` was drawing an always-on canvas ring behind
   every chokepoint's DOM dot; at world-map zoom this read as two separate marks. Removed the
   ring entirely — one clean DOM dot per chokepoint, with the existing hover/focus/active CSS ring
   providing the "target" affordance only on interaction.
3. **Chokepoints not visually aligned with the coastline** — `coastline.json` was built from
   Natural Earth's **110m** (coarsest) tier, which can't resolve narrow straits at all (Gibraltar
   14km, Bosphorus <1km) — they showed as solid unbroken coastline with no gap. Rebuilt from the
   **50m** tier (`scripts/build-coastline.py`, `SRC_URL` changed), with **Douglas-Peucker
   simplification** (`SIMPLIFY_EPSILON_DEG = 0.04`, ~4.4km) added to keep the file size sane — 357KB
   vs. a naive 881KB at 50m with no simplification (the old 110m file was 70KB but couldn't show
   the straits at all).

## 5. What's built — ship destination / ETA / cargo-type

Extends the *same already-integrated, free* aisstream.io connection — no new key, no new service.

- `relay.py`'s `FilterMessageTypes` now includes `"ShipStaticData"` alongside `"PositionReport"`.
  A `ShipStaticData` message only **enriches** a vessel we already have a live position for; it
  never creates an entry by itself.
- New fields on every vessel in `fleet-live.json`: `destination`, `eta` (`{month,day,hour,minute}`),
  `shipType` (raw AIS type code), `isCargo` (`true` for AIS types 70–79).
- Frontend (`js/fleetwatch.js`): cargo vessels render as a brighter, slightly larger dot; hovering
  **any** ship shows name / type / destination / ETA in the HUD instead of just lat/lon
  (`findShipNear()`, 12px hit radius).

**Real bug found and fixed while verifying this**: aisstream.io's metadata key is `MetaData`
(capital D) — the relay had `msg.get("Metadata", {})` (lowercase d) since the *original* Phase 2
build. Lat/lon/MMSI extraction had a fallback to the `PositionReport` body so ship positions kept
working regardless, but ship **names were silently always null**, and the new `ShipStaticData`
handler had no such fallback — every message was being dropped. One-line fix
(`scripts/fleet-relay/relay.py`); confirmed live afterward: names went from 0/135 to 128/135
populated, destinations started appearing (7/135 within ~2 minutes and climbing — AIS static data
broadcasts only every ~6 min per vessel, so this fills in gradually).

## 6. What's built — maritime news ticker

- **Sources used**: [gCaptain](https://gcaptain.com/feed/) and
  [Splash247](https://splash247.com/feed/) — both verified this session as real, standard
  WordPress RSS feeds with current articles.
- **Sources ruled out**: Lloyd's List (RSS page is subscriber-gated), Maritime Executive
  (`/rss.xml` just redirects to their homepage, not an actual feed), NewsAPI.org (free tier
  explicitly prohibits production/commercial use — 100 req/day, dev-only, 24h-delayed,
  200-char-truncated articles; paid plan starts at $449/mo).
- **`scripts/fetch-maritime-news.py`** — stdlib-only (no dependencies), pulls both feeds, keeps
  the 12 most recent items across both, writes `assets/data/maritime-news.json` (headline + link +
  source + publish date only — no full-article scraping, matches this project's cite-everything
  discipline).
- **VPS cron job** (not a systemd service — news doesn't need 5-second freshness):
  ```
  */20 * * * * /usr/bin/python3 /var/www/html/scripts/fetch-maritime-news.py >> /var/log/maritime-news-fetch.log 2>&1
  ```
- **`js/maritime-news.js`** — fetches `assets/data/maritime-news.json` once on page load, renders
  a simple linked list (source, title, date), escapes all external content before inserting into
  the DOM (titles come from a third-party feed — treated as untrusted input).
- `assets/data/maritime-news.json` is generated on the VPS, gitignored, never committed.

## 7. How to commit + deploy — step by step

Same underlying loop as `deploy.md` (push → SSH deploy script → curl-verify), spelled out fully
here with the Fleet Watch–specific restart rules.

### 7.1 Every normal change (HTML/CSS/JS, chart data, etc.)

```bash
git add <changed files>
git commit -m "..."
git push origin HEAD:main

ssh -i ~/.ssh/maritime-vps root@87.106.240.127 \
  '/usr/local/bin/maritime-deploy.sh && tail -1 /var/log/maritime-deploy.log'

curl -s -o /dev/null -w "%{http_code}\n" https://maritime-affairs.eu/insights.html
```

That's it for anything that doesn't touch the relay — CSS, `fleetwatch.js`, `routes.json`,
`coastline.json`, `observatory.json`, `maritime-news.js`, etc. are all served fresh by Apache on
every request; no restart needed.

### 7.2 When a `fleet-relay` restart IS required

The relay reads `chokepoints.json` and its own code **once at startup only** — it does not hot
reload. Restart after deploying if you changed:

- `scripts/fleet-relay/relay.py` (any logic change)
- `assets/data/chokepoints.json` (adding/removing/moving a chokepoint changes the subscribed
  bounding boxes)

```bash
ssh -i ~/.ssh/maritime-vps root@87.106.240.127 \
  '/usr/local/bin/maritime-deploy.sh && systemctl restart fleet-relay && sleep 2 && systemctl is-active fleet-relay'
```

### 7.3 Checking the relay is healthy

```bash
ssh -i ~/.ssh/maritime-vps root@87.106.240.127 'systemctl status fleet-relay'
ssh -i ~/.ssh/maritime-vps root@87.106.240.127 'journalctl -u fleet-relay -n 20 --no-pager'
curl -s https://maritime-affairs.eu/assets/data/fleet-live.json | python3 -c \
  "import json,sys,time; d=json.load(sys.stdin); print('age(s):', round(time.time()-d['generatedAt'],1), 'vessels:', d['vesselCount'])"
```

A fresh `age(s)` under ~10 and a non-zero vessel count means it's working. If `vesselCount` is
non-zero but every vessel's `destination`/`name` is null, give it a few minutes — `ShipStaticData`
broadcasts are much less frequent than position reports.

### 7.4 Checking the news cron job

```bash
ssh -i ~/.ssh/maritime-vps root@87.106.240.127 'crontab -l | grep maritime-news'
ssh -i ~/.ssh/maritime-vps root@87.106.240.127 'tail -20 /var/log/maritime-news-fetch.log'
curl -s https://maritime-affairs.eu/assets/data/maritime-news.json | python3 -c \
  "import json,sys; d=json.load(sys.stdin); print(len(d['items']), 'items')"
```

To force an immediate refresh instead of waiting up to 20 min:

```bash
ssh -i ~/.ssh/maritime-vps root@87.106.240.127 'python3 /var/www/html/scripts/fetch-maritime-news.py'
```

### 7.5 Cache gotchas (full detail in `deploy.md`)

- CSS/JS: `max-age=3600` — live on the server immediately, but a browser may serve a stale cached
  copy for up to an hour without a hard refresh (Cmd+Shift+R). Verify server state with
  `curl https://maritime-affairs.eu/js/fleetwatch.js | grep ...`, not just what the browser shows.
- HTML: always fresh (`max-age=0`).
- `assets/data/*.json`: `max-age=3600, must-revalidate` (not immutable) — same one-hour caveat as
  CSS/JS.

## 9. Not done / future work

- **VesselAPI** — researched this session: REST API, bulk bounding-box position queries,
  destination/ETA/draught, filtering by name/callsign/flag/type/year. Free tier has no stated hard
  request limit, but their docs don't confirm public-website/commercial-use terms. **Recommended
  role**: not a replacement for the aisstream relay (which is free, already streaming, and already
  proven live) — better as a future *single-vessel lookup* enrichment (e.g. click a ship → "look
  up full history" via VesselAPI on demand) than a second overlapping live-data system.
- **Port congestion / waiting-time index** — no confirmed free source found (MarineTraffic's
  congestion index and IHS Markit are the standard references, both paid/licensed). Would need a
  dedicated research pass if this is wanted.
- **Freight rate index** (e.g. Baltic Dry Index) — ruled out; licensed by the Baltic Exchange, no
  free API.
- **Bunker fuel prices** — not found in Eurostat; Ship&Bunker/Platts are the standard sources and
  are paywalled.
- **Piracy/incident reporting** — IMB Piracy Reporting Centre publishes reports but no free
  real-time API was confirmed this session; needs more research.
- **Weather/storm overlay near chokepoints** — genuinely feasible (NOAA or Open-Meteo both have
  real free APIs), just not built yet.
- **More Eurostat series** — feasible with no new key (port throughput by country, blue-economy
  jobs/GDP), same pattern as Phase 1, not built yet.
- **More news sources** — Lloyd's List would be a strong addition but requires a paid subscription
  for feed access; worth revisiting if a subscription is ever available.

## 10. Known limitations / deliberate tradeoffs

- The coastline is still simplified/illustrative ("engraved chart" style, see `design.md`) — not a
  navigation chart, and even at 50m some very narrow features may not render perfectly.
- Equirectangular (Plate Carrée) projection distorts high latitudes — Greenland/Russia/Antarctica
  look stretched. Chosen for simplicity/no-dependency reasons (see `CLAUDE.md`), consistent with
  the rest of the site's hand-rolled canvas approach.
- The live-ship feed is bounded to 15 small boxes (one per chokepoint), not literal "every ship on
  Earth." This is deliberate: aisstream's free tier and the VPS's ~1.8GB RAM couldn't reliably
  handle an unfiltered global feed. Visitors see real, live ships at every major strait/canal
  worldwide — just not the open ocean between them.
- The news ticker refreshes every 20 minutes from 2 sources — a curated headline list, not a
  real-time breaking-news feed.
